================================================================================
SECTION 1: MODULE OVERVIEW
================================================================================

The Assets module manages the full lifecycle of organizational assets:
- Asset registration with categorization, vendor, and document uploads
- Asset handover (assignment to employees) and return tracking
- Maintenance / service records
- Lookup tables (Category, Subcategory, Brand, Location, Tags)
- Barcode generation and printing

Files audited:
  Controller : protected/controllers/AssetsController.php
  Models     : Assets, AssetsCategory, AssetsSubcategory, AssetsBrand,
               AssetsLoc, AssetsTags, AssetsHandover, AssetsMaintenance,
               AssetsUploads
  Views      : protected/views/assets/ (18 files)

================================================================================
SECTION 2: ACCESS CONTROL
================================================================================

Role IDs used in Yii1:
  1 = admin
  2 = developer
  3 = client
  4 = sub_admin

Controller-level rules:
  - Admin (1) and Sub-admin (4) have full access to all actions.
  - Developer (2) has limited read/view access only.
  - Client (3) has no access.

Methods used:
  allowOnlyAdmin()      — restricts action to admin/sub-admin roles
  allowOnlyDeveloper()  — restricts action to developer role

Yii2 migration note:
  Replace with RBAC or simple role checks in beforeAction() / behaviors().
  Use Yii::$app->user->identity->usertype for role comparison.

4.1 Assets Model
────────────────────────────────────────────────────────────────────────────────

Standard rules:
  required     : brand_id, asset_cat_id, asset_subcat_id, vendor_id,
                 asset_loc, date_of_purchase, product_name
  integer      : brand_id, asset_cat_id, asset_subcat_id, vendor_id,
                 warranty, amc, status, asset_loc
  decimal      : bill
  string max250: model, service_contact, product_name
  safe         : warranty_start_date, warranty_end_date, amc_start_date,
                 amc_end_date, description, barcode, date_of_expire

Dynamic rules (via beforeValidate):
  - If warranty == 1:
      warranty_start_date → required
      warranty_end_date   → required
  - If amc == 1:
      amc_start_date → required
      amc_end_date   → required
  - Otherwise: those fields are optional.

Custom validator — compareDates():
  warranty_end_date  >= warranty_start_date  (if warranty=1)
  amc_end_date       >= amc_start_date       (if amc=1)
  date_of_expire     >= date_of_purchase

Custom validator — uniqueWhenNotDeleted():
  product_name must be unique among status != 0 records (excluding current id)
  model must be unique among status != 0 records (excluding current id)

SECTION 5: CONTROLLER ACTIONS — LOGIC SUMMARY
================================================================================

────────────────────────────────────────────────────────────────────────────────
5.1 actionAssetsindex()
────────────────────────────────────────────────────────────────────────────────
Purpose : List all assets with search/filter.
Logic   :
  - Load Assets model in search mode.
  - Pass GET params as search attributes.
  - Render grid with CActiveDataProvider (100 per page, order id DESC).
  - Search supports: product_name, barcode, model, brand, vendor,
    category, subcategory, location, tags (multi-select),
    warranty/amc flags, date range.

────────────────────────────────────────────────────────────────────────────────
5.2 actionAssetsadd()
────────────────────────────────────────────────────────────────────────────────
Purpose : Create a new asset.
Logic   :
  1. On POST: populate Assets model from $_POST['Assets'].
  2. Validate and save.
  3. On save success:
     a. Generate barcode: uniqid('MAE' . $model->id, true) → truncate to 10 chars.
     b. Save barcode back to record.
     c. Process file uploads for upload_type = 1,2,3,4:
        - File must not exceed 2MB.
        - Save to /uploads/assets_bill/{filename}.
        - Insert AssetsUploads record with asset_id, type, path, upload_type.
  4. Redirect to assetsindex on success.
  5. On GET: render empty form.

────────────────────────────────────────────────────────────────────────────────
5.3 actionAssetsupdate($id)
────────────────────────────────────────────────────────────────────────────────
Purpose : Edit existing asset.
Logic   :
  1. Load Assets record by $id (404 if not found).
  2. On POST: populate model with new values.
  3. Same file upload handling as add (appends new uploads, does not replace).
  4. Validate and save. Redirect to index on success.

────────────────────────────────────────────────────────────────────────────────
5.4 actionAssetsdelete($id)
────────────────────────────────────────────────────────────────────────────────
Purpose : Soft-delete an asset.
Logic   :
  1. Check if asset has active handover (status=1, out_date IS NULL).
     If yes → return JSON error "Asset is with employee, cannot delete."
  2. Set assets.status = 0.
  3. Set assets_maintenance.status = 0 for all matching asset_id.
  4. For handover records: if JSON asset_id array has only this asset,
     set assets_handover.status = 0.
  5. Return JSON {status: 1, message: "Deleted"}.

────────────────────────────────────────────────────────────────────────────────
5.5 actionAssetsview($id)
────────────────────────────────────────────────────────────────────────────────
Purpose : Show asset details in a modal.
Logic   : Load asset by $id. Render partial view _assetsview.

────────────────────────────────────────────────────────────────────────────────
5.6 actionAssetsmaintenance()
────────────────────────────────────────────────────────────────────────────────
Purpose : List all maintenance records.
Logic   : Load AssetsMaintenance in search mode with GET params. Render grid.

────────────────────────────────────────────────────────────────────────────────
5.7 actionAdd_assetsmaintenance()
────────────────────────────────────────────────────────────────────────────────
Purpose : Create a maintenance record.
Logic   :

  2. Validate (dynamic rules fire in beforeValidate).

  3. If payment_type changed to Free: reset payment_mode, invoice_bill,
     service_cost, gpay_number, bank_number to null/0.
  4. Validate and save.

5.9 actionDelete_assetsmaintenance($id)
────────────────────────────────────────────────────────────────────────────────

────────────────────────────────────────────────────────────────────────────────
5.10 actionAssetshandover()
────────────────────────────────────────────────────────────────────────────────
Purpose : List asset handovers (grouped by employee).
Logic   :

────────────────────────────────────────────────────────────────────────────────
5.12 actionAdd_assets_handover()
────────────────────────────────────────────────────────────────────────────────
Purpose : Assign one or more assets to an employee.
Logic   :

  4. Encode asset_ids as JSON: json_encode($asset_ids).
  5. Save. Redirect to assetshandover.

SECTION 6: BUSINESS RULES SUMMARY
================================================================================

1. SOFT DELETE everywhere — never hard delete. Use status = 0.

2. BARCODE FORMAT
   Generated once on first save: uniqid('MAE' + id, true) → 10 chars.
   Never regenerated after creation.

3. WARRANTY / AMC TOGGLE
   Checkbox toggles visibility of date fields AND makes them required.
   Server-side: beforeValidate() dynamically adds/removes required rules.

4. DATE VALIDATION ORDER
   purchase_date ≤ expiry_date
   warranty_start ≤ warranty_end
   amc_start ≤ amc_end
   handover in_date ≤ out_date

5. ASSET HANDOVER CONSTRAINTS
   - Cannot delete an asset that is currently with an employee
     (active handover = status=1 AND out_date IS NULL).
   - Cannot assign an asset already on active handover.
   - Multiple assets can be assigned in a single handover record (JSON array).

6. MAINTENANCE PAYMENT RULES
   - Free service: no payment fields required.
   - Paid service: payment_mode, invoice_bill, service_cost (> 0) required.
   - Paid + GPay: gpay_number required.
   - Paid + Bank: bank_number required.

7. UNIQUE LOOKUP NAMES (SOFT-DELETE AWARE)
   uniqueWhenNotDeleted() checks uniqueness only among non-deleted records.
   Cannot reuse a name that exists (status != 0) even under a different id.

8. LOOKUP DELETION PROTECTION
   Cannot delete a Category/Brand/Location/Tag if any asset references it.

9. CASCADING SOFT DELETE
   Deleting an asset → soft-deletes all linked maintenance records.
   If a handover record's JSON asset array contains only that asset,
   the handover is also soft-deleted.

10. FILE UPLOADS
    Max 4 files per upload_type. Max 2MB per file.
    Allowed types per section:
      Product Image  : jpg, jpeg, png
      Other bills    : jpg, jpeg, png, pdf, doc, docx
    Upload directory: /uploads/assets_bill/, /uploads/assets_maintenance/

7.4 Key Implementation Notes for Yii2
────────────────────────────────────────────────────────────────────────────────

POST CHECK:
  Use: Yii::$app->request->isPost
  NOT: $this->requirePost()  ← does not exist in Yii2

SOFT DELETE:
  status = 0 (never DELETE rows)
  All find() queries must add: ->where(['status' => 1]) or ['!=', 'status', 0]

PAYMENT STATUS FILTER (IMPORTANT):
  payment_type = 0 is a valid value, so do NOT use falsy check:
    WRONG : if (!$model->payment_type)
    RIGHT : if ($model->payment_type !== null && $model->payment_type !== '')

FILE UPLOADS:
  Use yii\web\UploadedFile::getInstance($model, 'billupload')
  Validate with FileValidator: size, extensions
  Store to Yii::getAlias('@webroot/uploads/assets_bill/')

BARCODE:
  Port BCGcode128 library usage as-is (composer package: barcode-bakery/barcode1d)
  Or generate via action returning PNG content with appropriate headers.

JSON HANDOVER asset_id:
  Store as JSON: json_encode($assetIds)
  Read with: json_decode($model->asset_id, true)
  For search: use MySQL JSON_CONTAINS in ActiveQuery

AJAX RESPONSES:
  Use Yii::$app->response->format = Response::FORMAT_JSON
  Return ['status' => 1, 'message' => '...']

UI COMPONENTS:
  Use Bootstrap 5 (yii\bootstrap5\*)
  All inputs: class="form-control form-control-sm" or "form-select form-select-sm"
  Action menus: Bootstrap dropdown with ⋮ (&#8942;) button
  Select2: include via asset bundle

NAVIGATION:
  Add link in backend/views/layouts/main.php under appropriate section.

DATABASE:
  DSN: mysql:host=127.0.0.1;port=3306;dbname=maestroerp
  User: root  Password: (empty)

7.5 Search Models in Yii2
────────────────────────────────────────────────────────────────────────────────

Create separate *Search models extending the base model.
Each search model:
  - Declares safe rules for all filter attributes
  - Implements search() returning ActiveDataProvider
  - Uses ActiveQuery with andFilterWhere() for nullable filters

AssetsSearch special filters:
  - tags (multi-select): andWhere(['in', 'id', ...]) or FIND_IN_SET
  - brand_id (multi-select): andFilterWhere(['in', 'brand_id', $this->brand_id])
  - from_date / to_date: andFilterWhere(['>=', 'date_of_purchase', ...])
  - category/subcategory/location (multi): andFilterWhere(['in', ...])

AssetsHandoverSearch special filter:
  - asset_id (JSON): use andWhere("JSON_CONTAINS(asset_id, :val)", [':val' => json_encode($id)])
